# 計画書: パーティ編成画面のパーティ操作・ボタン群の配置整列 (78_party_simulator_header_controls_alignment_plan.md)

本計画は、パーティ編成画面（`PartySimulator.tsx`）の上部コントロールバーにおいて、「パーティの検索・名前変更（Autocomplete）」と「アクションボタン群（クリップボードにコピー、新規作成、削除、パーティを保存）」の上下位置のズレを解消し、水平ラインを美しく揃える計画です。

---

## 1. 背景と課題分析

### ユーザー要望
> 「パーティ編成画面のパーティの検索・名前変更のコンポーネントと、クリップボードにコピー、新規作成、削除、パーティを保存のコンポーネントの位置がズレているのが気になります。揃えてください。」

### 現状のズレの原因
1. **親要素のアライメント**:
   - 行コンテナが `flex flex-col lg:flex-row gap-4 items-center justify-between` となっている。
   - 左側の `Autocomplete` は「ラベル（パーティの検索・名前変更）」＋「入力ボックス」の2段構成（高さ約 58〜60px）。
   - 右側のアクションボタン群にはラベルがなく、ボタンのみ（高さ約 34〜38px）。
   - `items-center`（垂直中央揃え）により、ボタン群がラベル込みの全体の中心に配置されるため、入力ボックスの垂直位置とボタン群の垂直位置が上下に約 9〜10px ズレて表示される。
2. **ボタン間の高さの不一致**:
   - `primary` / `secondary` ボタンは `py-2`（高さ約 38px）。
   - `danger` ボタン（削除）は `Button.tsx` の定義で `p-1.5`（高さ約 30px）となっており、ボタン同士でも高さ・ベースラインにわずかなバラつきがある。

---

## 2. 改善方針と設計

### 2.1. レイアウト配置の整列
- コントロール行の親コンテナのアライメントを `items-center` から **`items-end`**（下端揃え）に変更します。
  - これにより、左側の入力ボックス（Input）の下端と、右側のアクションボタン群の下端が同一のベースライン上にピタッと揃います。
  - ラベル「パーティの検索・名前変更」は入力ボックスの直上に綺麗に収まります。

```text
【改善前 (items-center)】
┌────────────────────────────────────────────────────────┐
│ [パーティの検索・名前変更]                             │
│                           [コピー] [新規] [削除] [保存]←中央に浮く
│ [パーティ名入力ボックス ]                              │
└────────────────────────────────────────────────────────┘

【改善後 (items-end)】
┌────────────────────────────────────────────────────────┐
│ [パーティの検索・名前変更]                             │
│ [パーティ名入力ボックス ] [コピー] [新規] [削除] [保存]←下端・高さが一直線
└────────────────────────────────────────────────────────┘
```

### 2.2. ボタンの高さ・パディングの統一
- 各ボタンのサイズ・パディングを統一（`h-10` または `py-2.5 px-3.5` 等、もしくは高さユーティリティで明示的に Input と同じ高さに揃える）。
- `danger` ボタン（削除ボタン）にも適切なパディング（`py-2 px-3` 等）を付与し、他のボタン（コピー・新規作成・保存）と同一の高さを維持。
- レスポンシブ表示（モバイル時は縦積み、タブレット・デスクトップ時は横並び）でも崩れないよう flex-wrap と幅を適切に維持。

### 2.3. UIアクセシビリティの確保
- ダークモード時のコントラスト比を維持（`AGENTS.md` のガイドライン遵守）。
- フォーカス時のアウトラインやホバーアニメーションの整合性を確保。
