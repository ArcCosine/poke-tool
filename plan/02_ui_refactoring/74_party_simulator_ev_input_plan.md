# 計画書: パーティ編成画面における努力値入力機能の追加 (74_party_simulator_ev_input_plan.md)

本計画は、パーティ編成画面（`PartySimulator.tsx`）の各ポケモンスロットにおいて、**ボタン形式ではなく数値入力（ステップ値: 0〜32）のみを用いて努力値を設定できる機能を追加する**計画です。

---

## 1. 背景と要件

### ユーザー要望
> 「パーティ編成画面でも努力値の入力ができるようにしてください。この画面は数値の入力のみの機能で大丈夫です。ボタンは不要です。」

### 主要要件と制約
1. **数値入力のみのインターフェース**:
   - `EvCalculator` で採用している `+1` / `-1` や `0` / `32` ボタンは**設置しない**。
   - 各ステータス（HP, 攻撃, 防御, 特攻, 特防, 素早さ）に対応する、直接入力可能な数値フィールド（`<input type="number">`）を提供する。
2. **換算表示の完全排除 (`AGENTS.md` ルール)**:
   - 0〜252への換算表示（`EV: 252` など）は**一切表示しない**。
   - 本ツールのステップ数値（0〜32）のみを扱い、ユーザーに余計な換算ラベルやテキストを提示しない。
3. **努力値の合計管理**:
   - 各ステータスの範囲: `0` 〜 `32`
   - 努力値合計の上限: 最大 `66` ステップ（ゲーム内合計510に相当）
   - 合計ステップ数を表示（例: `合計: 66/66`）し、上限超過を防ぐバリデーションを行う。
4. **UIアクセシビリティとダークモード高コントラスト**:
   - 入力枠、数値テキスト、ラベルにおいて、ライトモード・ダークモード双方で十分なコントラスト比を確保する。
   - モバイル・デスクトップの双方で崩れないレスポンシブ配置（デスクトップ 6列横並び、モバイル 3列×2行）。

## 2. UI・コンポーネント設計

### 2.1. 配置場所
`PartySimulator.tsx` の各ポケモンスロット内において、**「特性・性格・持ち物」セクションの直下（「技選択」の上）** に配置します。

```text
┌────────────────────────────────────────────────────────┐
│ [アイコン]  [ポケモン選択]                              [削除] │
│                                                        │
│ [特性選択]   [能力補正(性格)]   [持ち物検索]             │
│                                                        │
│ 努力値 (ステップ)                          合計: 66/66 │
│ ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐              │
│ │ H  │ │ A  │ │ B  │ │ C  │ │ D  │ │ S  │              │
│ │ 32 │ │  0 │ │  0 │ │ 32 │ │  2 │ │  0 │              │
│ └────┘ └────┘ └────┘ └────┘ └────┘ └────┘              │
│                                                        │
│ [技1] [技2] [技3] [技4]                                 │
└────────────────────────────────────────────────────────┘
```

### 2.2. 各数値入力フィールドの仕様
- **要素**: `<input type="number" min="0" max="32" step="1" />`
- **スタイリング**:
  - コンテナ: `bg-slate-50 dark:bg-slate-900/60 p-3 rounded-xl border border-slate-200 dark:border-slate-800 space-y-2`
  - 入力枠: `w-full text-center py-1.5 px-1 bg-white dark:bg-slate-950 border border-slate-300 dark:border-slate-700 rounded-lg text-sm font-bold text-slate-900 dark:text-slate-100 focus:outline-none focus:border-indigo-500 focus:ring-1 focus:ring-indigo-500`
  - ラベル: `text-xs font-bold text-slate-600 dark:text-slate-400 text-center block mb-1`
- **合計ステップ数表示**:
  - `text-xs font-semibold text-slate-600 dark:text-slate-400`
  - 合計が66の場合はアクセントカラー（`text-indigo-600 dark:text-indigo-400`）

### 2.3. データ更新ロジック
- ポケモンのインスタンス（`PokemonInstance`）の `evs` は内部的に `stepToEv(step)` で保存されているため、入力表示時は `evToStep(member.evs[stat])` でステップ値（0〜32）に変換して表示。
- 値変更時（`onChange`）:
  1. 入力値を `0` 〜 `32` の整数にクランプ。
  2. 他のステータスのステップ合計を算出。
  3. 全体合計が 66 を超えないよう `Math.min(cleanStep, 66 - otherTotal)` で制御。
  4. `stepToEv(newStep)` で EV 値に変換し、`updateMember(index, { evs: updatedEvs })` を呼び出して更新。

   - 各ポケモンスロット内（特性・性格・持ち物の直下）に、H, A, B, C, D, S の6項目の数値入力欄（`<input type="number" min="0" max="32" step="1" />`）を配置。
