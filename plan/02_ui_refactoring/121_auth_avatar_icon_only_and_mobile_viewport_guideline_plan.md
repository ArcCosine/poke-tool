# 計画書: ログイン時アバターアイコン限定表示およびモバイル幅遵守ガイドラインの策定

## 1. 概要と背景

### 1.1 現状の課題
- ログイン後、ヘッダーにユーザー名（最大 120px）とアバター、ログアウトボタン、言語セレクター、テーマ切替ボタンが横並びになる。
- これにより、スマートフォン（幅 320px〜390px）においてヘッダーの合計幅が画面幅を超過し、画面全体の横スクロールやレイアウト崩れ・押し広げが発生するケースがある。

### 1.2 目的
1. **ログイン時ユーザー表示のコンパクト化**:
   - ユーザー名のテキスト表示を廃止し、**アイコン（アバター画像またはデフォルトアイコン）のみ**を表示する設計へ変更する。
   - これによりヘッダー右側の専有幅を大幅に削減し、スマホ幅でも自然に収まるようにする。
2. **`AGENTS.md` への設計規約の追加**:
   - どのようなコンポーネントを設計・実装する際でも、スマートフォンの画面幅（最小 320px〜375px）を超過（横スクロールやはみ出し）させない設計思想・実装規約を `AGENTS.md` に明文化し、今後の開発で厳格に遵守する。

---

## 2. 具体的な変更設計

### 2.1 `src/components/common/AuthButton.tsx` の改修
- **ユーザー名テキストの削除**:
  - `<span className="... max-w-[80px] sm:max-w-[120px] truncate">{user.name}</span>` を削除。
- **アバターアイコンの表示**:
  - `user.avatarUrl` がある場合は丸型画像（`w-8 h-8 rounded-full object-cover`）、ない場合はデフォルトアイコン（`i-lucide-user`）を丸型背景枠内に表示。
  - アクセシビリティおよび視認性のため、コンテナまたは画像に `title={user.name}` および `aria-label={user.name}` を付与。
- **ログアウトボタンの最適化**:
  - モバイルでの押し広げを防止するため、スマホ幅ではアイコンのみ（またはパディングを最適化）とし、PC幅（`sm:` 以上）でテキストを表示するか、すっきりとしたアイコンボタン構成にする。

### 2.2 `AGENTS.md` への設計規範追記
- 新セクション「**レスポンシブ設計とモバイルビューポートの設計方針 (スマホ幅超過・横スクロールの絶対防止)**」を追加。
- 以下の原則を規定：
  1. **スマホファースト・幅超過の絶対禁止**:
     - 最小画面幅（320px〜375px）において、横スクロール・要素のはみ出し・親コンテナの不本意な押し広げを発生させないこと。
  2. **コンテンツと文字の省略・レスポンシブ制御**:
     - ヘッダー等の高密度エリアではテキストの露出を最小限にし、アイコンやアバターを活用する。
     - テキスト要素には `truncate` や `break-words`、フレックスコンテナには `min-w-0` を適切に適用する。
  3. **固定幅（Fixed Width）の排除**:
     - `w-[xxxpx]` 等の大きな固定幅指定を避け、`max-w-full` やパーセンテージ、グリッドを活用する。
