# 計画書: 努力値調整入力のボタンUI刷新と専用インターフェイス設計 (69_ev_button_input_redesign_plan.md)

本計画は、努力値計算ツール (`EvCalculator.tsx`) における努力値入力の操作性を改善するため、現在のスライダー形式を廃止し、`+1` / `-1` ボタンや大型化した `0` / `32` ボタンを備えた専用入力インターフェイス (`EvStatInput.tsx`) を設計・実装する計画です。
※努力値（0〜252等）への換算表示は行わず、本ツールのステップ数値（0〜32）のみを直接操作・表示します。

---

## 1. 背景と目的
現在、`EvCalculator.tsx` の努力値入力はスライダー (`<input type="range">`) と数値入力、および極小の `0` / `32` ボタンで構成されています。
しかし、以下の課題があります：

1. **スライダーの操作性**:
   - マウスやタッチ操作で目的の数値（0〜32 の各段階）に合わせるのが難しく、誤操作が発生しやすい。
2. **最小値・最大値ボタンの視認性・押しやすさ**:
   - 現在のボタンは `text-[10px]`、`px-1` と極めて小さく、視認性が低くクリックしづらい。
3. **直感的なステップ調整の不足**:
   - 「実数値をあと1上げたい / 下げたい」という微調整が頻繁に行われるが、手軽に1ずつ増減できるボタンが存在しない。

これらを解決するため、スライダーを廃止し、**「+1」「-1」による段階的調整ボタン**、および**大きく押しやすい「0」「32」専用ボタン**を統合した専用インターフェイスを設計します。また、余計な換算表示（EV換算ラベル等）は排除し、0〜32の直接的な入力に集中できるUIとします。

---

## 2. 仕様と要件

### 2.1. 努力値ステップの仕様
- 本ツールでは各ステータス 0〜32 ステップ。
- 全ステータスの合計上限は 66 ステップ。
- ステップ値が 1 変わることで実数値が 1 変化するため、`+1` / `-1` ボタンが最も直感的で実用的な調整単位となります。

### 2.2. ボタン構成とインターフェイス設計
各ステータス行の努力値入力エリアを、以下の横並びボタングループに刷新します：

```text
[ 0 ]   [ -1 ]   [  32  ]   [ +1 ]   [ 32 ]
(Min)   (減算)   (入力欄)   (加算)   (Max)
```

1. **「0」ボタン（最小値リセット）**:
   - クリックすると該当ステータスの数値を `0` にリセット。
   - 文字サイズ: `text-sm font-semibold`
   - スタイル: ニュートラルなボタンスタイル（グレー系）。
   - 現在値が `0` の場合は disabled（非活性）。
2. **「-1」ボタン（デクリメント）**:
   - クリックすると数値を 1 減らす。
   - 文字サイズ: `text-sm font-bold`
   - 現在値が `0` の場合は disabled。
3. **数値入力欄（直接入力 / 現在値表示）**:
   - 直接キーボードから 0〜32 を打ち込み可能。
   - `w-14` 程度で中央揃え、太字で読みやすいフォント。
   - `min=0`, `max=32`、上限超過時は許容最大値に自動補正。
4. **「+1」ボタン（インクリメント）**:
   - クリックすると数値を 1 増やす。
   - 文字サイズ: `text-sm font-bold`
   - 現在値が 32、または合計上限（66）に達している場合は disabled。
5. **「32」ボタン（最大値MAX）**:
   - クリックすると該当ステータスを最大値（`32`、または残り枠 `allowedMax`）に設定。
   - 文字サイズ: `text-sm font-bold`
   - スタイル: アクセントカラー（インディゴ系）。
   - すでに 32、または残り枠がない場合は disabled。

## 3. コンポーネント設計

### 3.1. `EvStatInput.tsx` のインターフェイス
コンポーネントを `src/components/EvCalculator/EvStatInput.tsx` として分離し、単体でテスト・メンテナンス可能にします。

```typescript
export interface EvStatInputProps {
  stat: string;
  value: number; // 0〜32
  onChange: (newValue: number) => void;
  maxAllowed: number; // 残り枠を考慮したこのステータスに設定可能な最大値 (0〜32)
  min?: number; // デフォルト 0
  max?: number; // デフォルト 32
  disabled?: boolean;
}
```

### 3.2. スタイリング仕様
- Tailwind CSS を使用し、ダークモード（`dark:`）とライトモードの双方で統一感のあるプレミアムな外観を提供。
- ボタンサイズ: タップ・クリックしやすいよう `h-9`（36px）以上のタッチターゲットを確保。
- トランジション: `transition-all active:scale-95 duration-150` による心地よい押下フィードバック。

## 4. TDD (テスト駆動開発) 計画

### Step 1: 単体テストの作成 (`EvStatInput.test.tsx`) (Red)
以下のテストケースを作成し、最初は失敗することを確認：
1. 現在のステップ値（例: 0, 16, 32）が入力欄に正しく表示されること。
2. `+1` ボタンをクリックすると `onChange(value + 1)` が呼び出されること。
3. `-1` ボタンをクリックすると `onChange(value - 1)` が呼び出されること。
4. `0` ボタンをクリックすると `onChange(0)` が呼び出されること。
5. `32` ボタンをクリックすると `onChange(maxAllowed)` が呼び出されること。
6. 現在値が `0` の時、`-1` ボタンおよび `0` ボタンが `disabled` であること。
7. 現在値が `maxAllowed` の時、`+1` ボタンおよび `32` ボタンが `disabled` であること。
8. 入力欄に数値を直接入力した場合、クランプされて `onChange` が発火すること。
