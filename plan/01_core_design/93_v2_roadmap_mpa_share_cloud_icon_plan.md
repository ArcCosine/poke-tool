# 計画書 93: MPA化・SNS共有・UI改善・アイコン作成およびクラウド同期設計

## 1. 概要
本計画は、本番環境デプロイ後のフィードバックに基づき、以下の機能拡張・改修・新規設計を行うものです。

1. **オリジナルアイコンの作成**: プロジェクト専用のSVGアイコンおよびファビコンの作成・配置
2. **MPA (マルチページアプリケーション) への移行**: 火力耐久ランキング、努力値調整、パーティ編成を独立したHTMLページとして再構成
3. **努力値調整ページのスマホ表示修正**: ステータス実数値と調整ボタンの重複によるタップ不可不具合の解消
4. **パーティ保存通知のDialog化**: `alert()` を廃止し、統一されたモーダルダイアログによる通知への改善
5. **SNSシェア機能（英数字のみのURLパラメータ）**: 努力値調整およびパーティ編成のデータを英数字のみ（%エンコード不使用）でURL引数化し、復元・シェア可能にする機能
6. **クラウド認証・データ同期設計**: Google/X (Twitter) 認証を利用したブラウザ横断のパーティデータ同期のアーキテクチャ設計と提案

## 2. 要件と詳細設計

### 2.1 専用アプリアイコンの作成
- **コンセプト**: ポケモンの象徴（ボール形状）、対戦・火力（剣）、耐久（盾）、データ分析（幾何学的クリスタル・六角形レーダー）を融合したクリーンで洗練されたモダンベクターデザイン。
- **配置先**:
  - `public/favicon.svg`（ファビコン）
  - ヘッダーロゴアイコン（全ページのナビゲーションバーに反映）
  - 各種HTMLの `<link rel="icon" ...>` を統一

### 2.2 MPA (マルチページアプリケーション) 化
- **背景**: SPA（単一ページ内のタブ切替）から、各ツールが独自のURLとHTMLを持つMPAに移行することで、ブックマークの利便性向上、ページごとのSEO/OGP最適化、SNSシェア時のURL整合性を確保する。
- **ページ構成**:
  - `/index.html`: ダッシュボード / トップページ（ツール紹介・ナビゲーション）
  - `/ranking.html`: 火力・耐久ランキング（旧 `StatSearch`）
  - `/ev-calculator.html`: 努力値調整ツール（旧 `EvCalculator`）
  - `/party.html`: パーティ編成・相性チェッカー（旧 `PartySimulator`）
  - `/privacy.html`, `/disclaimer.html`, `/terms.html`: 法的ページ（既存）
- **Vite設定 (`vite.config.ts`)**:
  - `build.rollupOptions.input` に `ranking`, `ev-calculator`, `party` を追加。
- **共通レイアウト・ナビゲーション**:
  - 共通の `Header`（ロゴ、言語切替、テーマ切替）
  - 共通の `BottomNav` / `Navbar`（現在のページをアクティブ表示し、`<a href="/...">` で遷移）
  - 共通の `AppProvider`（テーマや言語設定は `localStorage`、パーティデータは `IndexedDB` でドメイン全体で自動共有）

### 2.3 努力値調整ページのスマホ表示修正 (UI改善)
- **問題の原因**:
  - 幅 < 640px のモバイル画面において、ステータス行（ラベル・種族値・増減ボタン・実数値）の12列グリッドで、増減ボタン群（幅約208px）が割り当て領域（約130px）をはみ出し、右側の実数値表示と重なって `+1` や `32` ボタンがタップできなくなる。
- **改善アプローチ**:
  - モバイル画面（`sm:` 未満）では2段構成レイアウトを採用：
    - **上段**: ステータス名（HP, 攻撃等） + 性格補正記号 + 種族値（左側） ─── 実数値（右側に大きく太字で強調表示）
    - **下段**: 努力値ステップ調整コントロール（`0`, `-1`, `[ 入力欄 ]`, `+1`, `32`）を等幅かつ押しやすいサイズ（タッチターゲット 44px以上確保）で横一列にゆったり配置。
  - PC・タブレット画面（`sm:` 以上）では従来の横並びグリッドレイアウトを維持。

### 2.4 パーティ保存時のDialog表示化
- **現状**: `alert(t('partySimulator.partySaved'))` がブラウザ標準のアラートを呼出。
- **改善案**:
  - プロジェクトのデザインシステムに適合したモーダルダイアログ（またはトースト通知コンポーネント）を作成。
  - 保存成功時に「パーティを保存しました」のタイトル、パーティ名、確認チェックアイコンとともに洗練されたダイアログを表示（自動フェードアウトまたは「OK」ボタン）。

### 2.5 SNSシェア機能（英数字パラメータによるデータ復元）
- **要件**:
  - URL引数（クエリまたはハッシュ）に英数字のみ（`%` や記号を使わない）を用いてデータを圧縮エンコード。
  - 努力値調整: ポケモン、もちもの、性格、努力値（6ステータス）、技4つをエンコード/デコード。
  - パーティ編成: 最大6体分の構成をエンコード/デコード。
- **エンコード設計（独自バイナリパッキング + Base64URL/Base62）**:
  - **努力値調整（1匹）**:
    - ポケモンID: 16bit (0〜65535)
    - 性格ID: 5bit (0〜24)
    - 持ち物ID: 10bit (0〜1023)
    - 努力値: 6ステータス × 6bit (各0〜32ステップ) = 36bit
    - 技ID: 4技 × 11bit (0〜2047) = 44bit
    - 合計: 111bit ≈ 14バイト。
    - 14バイトのバイナリを **Base64URL**（`A-Z`, `a-z`, `0-9`, `-`, `_`）または **Base62**（`0-9`, `a-z`, `A-Z` のみ）に変換。
    - 結果: わずか **約19文字のクリーンな英数字** のみ！
    - 例: `https://poke-tool.pages.dev/ev-calculator.html?s=7bXk9aBc...`
  - **パーティ編成（最大6匹）**:
    - 各ポケモン14バイト × 最大6体 = 最大84バイト。
    - Base62/Base64URL化すると約112文字の英数字。
    - 例: `https://poke-tool.pages.dev/party.html?p=7bXk9a...`
  - **UI**:
    - 「URLをコピー」ボタン（クリップボードにコピー＋完了通知）
    - 「X (Twitter) でシェア」ボタン（Web Intent URLを開く）
    - ページを開いた際、URLにパラメータが存在する場合は自動的にデータを読み込んで画面に復元（パーティの場合は「インポートされたパーティ」として反映または閲覧可能にする）。

### 2.6 クラウド同期・認証機能の設計と提案
- **目的**: 異なる端末（PCとスマホなど）や別ブラウザ間で、パーティデータをシームレスに同期・バックアップする。
- **インフラ要件**:
  - 本ツールは現在 Cloudflare Pages（静的フロントエンド）で運用中。
- **推奨アーキテクチャ案**:
  - **【推奨】Firebase Authentication + Cloud Firestore**
    - **選定理由**:
      1. サーバー不要（Cloudflare Pagesの静的構成のまま導入可能）
      2. Google 認証、X (Twitter) 認証のプロバイダーが標準で用意されている
      3. オフラインキャッシュ（IndexedDBとシームレスに連携可能）
      4. 無料枠が非常に広く、個人開発・コミュニティツールに最適
    - **同期フロー**:
      1. 未ログイン時: 従来の IndexedDB のみで動作（ログイン不要で全機能が使える）
      2. ユーザーが「ログインして同期」を選択（Google または X）
      3. ログイン成功時: クラウド上のパーティデータとローカルデータをマージ
      4. パーティの保存・削除時にローカルとFirestoreの双方に反映
- **事前準備・ユーザー作業**:
  - Firebase プロジェクトの作成
  - Google Cloud Console / Twitter Developer Portal での OAuth クライアントID・シークレットの登録
