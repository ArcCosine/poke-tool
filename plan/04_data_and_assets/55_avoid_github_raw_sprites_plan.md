# ポケモン画像のGitHub Raw直リンク回避計画

## 概要
現在、ポケモンのスプライト（画像）は `raw.githubusercontent.com` から直接フェッチされており、アクセス過多（HTTP 429 Too Many Requests 等）が発生するリスクがあります。この問題を回避し、表示速度と信頼性を向上させるための計画を策定します。

---

## 提案する代替アプローチ

### 提案 1: jsDelivr CDN の利用 (最も推奨・低コスト)
GitHub リポジトリのファイルを全世界のエッジサーバーでキャッシュ・配信する高速なパブリック CDN **jsDelivr** を利用します。
- **画像URLの置換**:
  - 旧: `https://raw.githubusercontent.com/PokeAPI/sprites/master/sprites/pokemon/${id}.png`
  - 新: `https://cdn.jsdelivr.net/gh/PokeAPI/sprites@master/sprites/pokemon/${id}.png`
- **メリット**: 変更は画像の URL プレフィックス文字列の変更のみで済み、一切のライブラリ追加やビルドサイズの増加がありません。GitHub Pages / Raw のレートリミットを完全に回避でき、画像のロードも劇的に高速化されます。

### 提案 2: ブラウザの Cache API によるローカルキャッシュ (ローカルファースト強化)
画像のフェッチ成功時に、ブラウザの Cache API（Service Worker または手動キャッシュ）を利用して画像をローカルに保存します。
- **メリット**: 一度読み込んだ画像は二度と外部リクエストが発生しないため、オフライン動作およびプライバシーが最大化されます。
- **デメリット**: 初回のアクセス過多を完全に防ぐことはできません（初回はやはり外部から取得する必要があるため）。

---

## 開発ロードマップ (TDDの遵守)

### ステップ 1: アプローチの決定
- ユーザーにどのアプローチ（または組み合わせ）で実装を進めるか確認し、合意を得ます。
- 提案 1（jsDelivr CDN）は最も簡単で効果的であるため、こちらを推奨します。

### ステップ 2: 画像表示部分の書き換え
- `PartySimulator.tsx` や `PokemonSearchModal.tsx` などの画像 URL 生成部分を、選択されたアプローチ（jsDelivr 等）の URL に書き換えます。

### ステップ 3: テストコードとビルドの検証
- テストコード内に GitHub Raw の URL をハードコードしているアサーションがあれば、それらを新しい URL に追記・修正します。
- すべてのテストが Green になることを確認し、本番ビルドを実行します。
