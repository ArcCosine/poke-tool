# 07_implementation_roadmap.md - 実装ロードマップ

本ドキュメントでは、計画 01〜06 に基づき、各機能を具体的にどの順序で実装・統合していくかを示す実装ロードマップを計画します。

---

## 1. 実装ステップとスケジュール

各機能が相互に依存するため、以下の優先順位に従って段階的に実装します。

### Step 1: プロジェクト初期化と開発・テスト環境の構築 (土台)
- **タスク**:
  - `Vite + React + TypeScript` プロジェクトの作成。
  - UnoCSS（`unocss`、`@unocss/vite` 等）のインストールと設定（`uno.config.ts` の作成）。
  - UnoCSSのプリセット（Uno, Attributify, Icons）のセットアップ。
  - **テスト環境の構築**: `Vitest`、`@testing-library/react`、`happy-dom` などの単体テスト環境をインストール・セットアップ。
  - プレミアムなデザインのためのカスタム設定（共通HSLカラー、ガラスモフィズム用ショートカット定義、ベースCSSリセットなど）。
  - ナビゲーションおよびダッシュボード全体の骨組み（タブ切り替えなど）の実装。

### Step 2: データ基盤と火力・耐久検索機能の実装 (コア機能 1)
- **タスク**:
  - 主要なポケモンデータおよび技データの静的JSONファイルを作成・配置。
  - **TDDの実行**: 性格補正や努力値を含むステータス実数値計算関数、および火力・耐久指数の計算ロジックのテストコードを先に作成。
  - テストをパスする計算ロジックの実装（TypeScript）。
  - 最大火力/最大耐久のランキング表示（Top 30）およびタイプ・物理/特殊フィルタリング画面の構築（コンポーネントテストを含む）。

### Step 3: パーティシミュレーターの実装 (コア機能 2)
- **タスク**:
  - 6匹のポケモンを登録できるパーティエディタUIの構築。
  - **TDDの実行**: タイプ防御一貫性の集計ロジック、攻撃範囲（打点不足）の判定ロジックについて、まずテストコード（Vitest）を記述。
  - テストをパスする分析ロジックの実装（TypeScript）。
  - 分析結果（弱点タイプ、打点不足など）を可視化するUI（グリッド相性表、レーダーチャート等）の実装（コンポーネントテストを含む）。
  - `localStorage` を用いたパーティデータの永続化。

### Step 4: WASM環境構築と画像解析プロトタイプ (コア機能 3 - 前半)
- **タスク**:
  - Rust + `wasm-pack` によるWASMモジュール環境のセットアップ。
  - ViteとWASM의 連携設定（非同期インポートの確認）。
  - JSから渡された画像ピクセルデータを受け取るRust APIの疎通確認。

### Step 5: 画像解析アルゴリズムの実装とパーティ取り込み (コア機能 3 - 後半)
- **タスク**:
  - 画像正規化（Canvas上でのアスペクト比調整）の実装。
  - **TDDの実行**: Rust側で、テンプレートマッチングによる特定処理や、カラーヒストグラム解析、努力値グラフの二値化・輪郭検出などのロジックについて、`cargo test` 等で事前にテストを記述。
  - テストをパスする画像解析アルゴリズムの実装（Rust / WASM）。
  - 認識したテキスト・ステータスデータをパーティシミュレーターへインポートする連携部分の実装。

### Step 6: 磨き込みと最終調整
- **タスク**:
  - UI全体のマイクロアニメーション、トランジションの追加。
  - モバイル対応（レスポンシブデザイン）の調整。
  - エラーハンドリングと最終テスト。

---

## 2. 開発への移行基準

すべての計画ドキュメント（01〜07）について、ユーザーからの最終承認が得られた段階で、実際のコード作成（Step 1）を開始します。
承認が得られるまでは、ソースコードの記述やコマンドの実行は行いません。
