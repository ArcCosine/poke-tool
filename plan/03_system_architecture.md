# 03_system_architecture.md - システムアーキテクチャおよびデータ設計

本ドキュメントでは、Vite + React (TypeScript) をベースとしたアプリケーションのディレクトリ構成、コンポーネント設計、データ設計、および WebAssembly (WASM) 連携方針について計画します。

---

## 1. ディレクトリ構成案

静的SPAとWASM開発の環境を1つのリポジトリで管理するモノレポ構成（または単一リポジトリ内にWASMソースを同居させる構成）を想定しています。

```text
poke-tool/
├── AGENTS.md
├── README.md
├── package.json
├── vite.config.ts
├── plan/                    # 計画ドキュメント
│   ├── 01_initial_plan.md
│   ├── 02_technology_selection.md
│   └── 03_system_architecture.md
├── src/                     # フロントエンドソース
│   ├── main.tsx
│   ├── App.tsx
│   ├── components/          # 共通UIコンポーネント (UIライブラリに依存しないプレミアム設計)
│   │   ├── Common/          # ボタン、カード、モーダルなど
│   │   ├── ImageAnalyzer/   # 画像分析関連コンポーネント
│   │   ├── StatSearch/      # 最大火力/耐久検索関連コンポーネント
│   │   └── PartySimulator/  # パーティシミュレーター関連コンポーネント
│   ├── hooks/               # カスタムフック (WASM呼び出し、データ計算ロジック等)
│   ├── data/                # ポケモン、技、特性、タイプ相性などの静的JSONデータ
│   ├── styles/              # デザインシステム用CSS (CSS Variables, HSLカラー定義)
│   └── utils/               # 汎用ヘルパー関数
├── wasm/                    # WebAssemblyソースディレクトリ (Rust等)
│   ├── Cargo.toml
│   └── src/
│       ├── lib.rs           # 画像解析・推論などのロジック
│       └── image_processing.rs
└── public/                  # 静的アセット (画像、ビルド済みWASMバイナリ等)
```

## 2. 画面構成案

ユーザーが利用する機能はタブまたはシンプルなナビゲーションで切り替え可能にします。

1. **ダッシュボード / ナビゲーション**:
   - リッチなダークテーマとスムーズなトランジションを持つサイドバーまたはヘッダー。
2. **画像分析画面 (Image Analyzer)**:
   - ドラッグ＆ドロップによる画像アップロードエリア。
   - WASMによる解析プログレスバー。
   - 解析結果（ポケモン名、性格、努力値等）の確認・編集フォーム。
3. **火力・耐久検索画面 (Stat Search)**:
   - ポケモン名、技、タイプのフィルタリングフォーム。
   - 計算結果（Top 30）のプレミアムテーブル/グリッド表示。
4. **パーティシミュレーター画面 (Party Simulator)**:
   - 現在のパーティ（6匹）の登録リスト。
   - タイプ相性の弱点・補完関係を視覚化したレーダーチャートやヒートマップ。
   - 相性・耐久・火力を考慮した「苦手なタイプ / 対策が必要なポケモン」の自動提案セクション。

## 3. WebAssembly (WASM) 連携方針

### 言語選定
- **Rust (`wasm-bindgen` / `wasm-pack`)** を採用。
  - メモリ安全性が高く、画像処理ライブラリ（`image` クレートなど）が充実しているため、ピクセルデータの解析に最適。
  - Viteのプラグイン（`vite-plugin-wasm`）を使用することで、JS/TS側から通常のモジュールのように非同期インポート可能。

### 画像解析の流れ
1. **JS/TS側**:
   - `input[type="file"]` や `canvas` から画像のピクセルデータ（`Uint8Array` など）を取得。
2. **WASM (Rust) 側**:
   - ピクセルデータを受け取り、特徴抽出（文字領域の切り出し、アイコンのテンプレートマッチングなど）を実行。
   - ポケモンの名前や努力値などの候補をJSONまたは構造体としてJS側に返す。
3. **JS/TS側**:
   - 取得したデータを状態（State）に反映し、UI上に表示してユーザーが確認・修正できるようにする。

## 4. データ設計 (静的データ)

サーバー費用をかけないため、データベースは持たず、以下のように設計します。

- **静的マスターデータ**:
  - ポケモンの種族値、タイプ、覚える技、性格補正などのマスターデータを `src/data/` 配下に JSON 形式で定義。
- **ユーザーデータの一時保存**:
  - 作成したパーティ情報や解析履歴は、ブラウザの `localStorage` または `IndexedDB` に保存し、ページをリロードしてもデータが消えないようにします。
