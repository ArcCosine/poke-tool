# 15_OCRスクリプトのRust移植計画

本計画は、Pythonで作成した `OnnxOCR` による文字認識・座標抽出スクリプトを Rust に移植し、`src/wasm-analysis` ディレクトリ配下の構成を再構築する手順を定義します。

---

## 1. 移植における設計とアプローチの選択

本プロジェクトはブラウザで動作するWebアプリケーションであるため、画像解析エンジンは WebAssembly (WASM) にコンパイルできる必要があります。これを踏まえ、以下の2つのアプローチを検討します。

### アプローチ A: WASMハイブリッド方式（強く推奨）
* **構成**: 
  * **ONNX推論 (モデルロードと実行)**: ブラウザネイティブの `onnxruntime-web` を用いて **TypeScript/JavaScript 側**で実行。
  * **前処理・後処理**: Pythonで行っていた画像前処理（テンソル変換）および後処理（DBNetの出力からバウンディングボックスの復元、SVTR/LCNetのCTCデコード）の重いロジックを **Rust (WASM) 側**に移植する。
* **メリット**:
  * ブラウザ上で非常に高速に動作する（WebGLやWebAssemblyスレッドの恩恵を受けられる）。
  * 既存のプロジェクト構成（`npm run dev` 等での `wasm-pack build`）が壊れず、クリーンに統合できる。
* **デメリット**:
  * 推論部分のみ JavaScript 側で実行するため、Rust単一での推論コードにはならない。

### アプローチ B: ネイティブ Rust 完結方式
* **構成**: Rustの `ort` クレート（ONNX Runtimeラッパー）を用い、モデルのロードと推論を完全に Rust 内で完結させる。
* **メリット**:
  * Pythonスクリプトと全く同じ動作をする Rust の単一バイナリ/テストコードを作成できる。
* **デメリット**:
  * `ort` クレートは `wasm32-unknown-unknown`（ブラウザWASM）ターゲットでのビルドに対応していない（またはビルド設定が極めて困難で実用的でない）ため、Webアプリケーションとしてのビルドが壊れてしまいます。

> [!IMPORTANT]
> 本プロジェクトはWebアプリケーションとしてブラウザ上で「ローカルファースト」で動作させる大前提（`AGENTS.md`参照）があるため、プロジェクトの開発環境とアプリ動作を正常に保つために、**【アプローチ A (WASMハイブリッド方式)】**での移植を推奨します。

---

## 2. アプローチAに基づく実装・設計詳細

### (1) Rust 側（`src/wasm-analysis`）の実装内容
既存の `lib.rs` のコード（二値化、フォントマッチングOCR、レーダーチャート解析）は全て廃止し、以下のロジックに置き換えます。

1. **DBNetの後処理 (Post-Processing)**:
   * 推論結果（確率マップ）から閾値判定によりテキスト領域を検出し、バウンディングボックスの座標リストに復元する。
2. **CTCデコーダー (CTC Decoder)**:
   * 認識モデルから出力された確率テンソル（TimeStep × ClassNum）を受け取り、各ステップの最大確率の文字インデックスを取得する。
   * 連続する同一文字の統合と、ブランク文字の除去を行う。
   * 指定された文字辞書（日本語・英語・韓国語）のインデックスに基づいて文字列へマッピングする。

### (2) TypeScript / UI 側（`src/utils/ocr.ts` 等）の実装内容
1. `onnxruntime-web` を用いて、テキスト検出モデル (`det.onnx`) と認識モデル (`rec.onnx`)、および韓国語モデルを初期化・実行する。
2. 検出モデルの出力を Rust (WASM) に渡してバウンディングボックスの一覧を受け取る。
3. 抽出された各矩形画像をクロップし、認識モデルに入力して推論を行う。
4. 認識モデルの出力を Rust (WASM) に渡して CTC デコードを適用し、最終的な文字列（日・英・韓）を取得する。
