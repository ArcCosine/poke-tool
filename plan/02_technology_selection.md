# 02_technology_selection.md - 技術フレームワークの選定とホスティング戦略

本ドキュメントでは、サーバー代金を最小（ほぼ無料）に抑えつつ、ローカルWASMによる画像解析と分析ツールをスムーズに動作させるためのフロントエンド技術とホスティングの選定について提案します。

## 1. 前提条件と方針
- **サーバー処理の最小化**: 画像解析、検索機能、パーティシミュレーターのすべての処理をブラウザ側（クライアントサイド）で実行する。
- **静的配信の活用**: ビルド結果を静的なHTML/CSS/JSとWASMファイルのみにし、静的ホスティングサービスを活用することでサーバー維持費を **無料（0円）** に抑える。

---

## 2. 採用するホスティングサービス
本プロジェクトでは、以下の理由から **Cloudflare Pages** を採用します。
- **理由**: 転送量（帯域制限）が無制限であること、またビルド時間やプロジェクト制限の無料枠が他の静的ホスティング（VercelやNetlifyなど）に比べて非常に強力であるため。サーバー維持費は **完全に無料 (0円)** で運用可能です。

---

## 3. フロントエンドフレームワークの決定
ユーザー投票の結果、**Vite + React (TypeScript)** を採用します。
- **決定理由**: 静的SPAとしてビルドでき、かつWASMとの統合（`vite-plugin-wasm`等によるインポート）が極めて容易であるため。

---

## 4. CSS / スタイリング技術の選定

プレミアムでリッチなデザイン（ダークモード、HSLカラー、ガラスモフィズム、アニメーション等）を実現しつつ、パフォーマンスとビルド時の安定性を両立させるため、**UnoCSS** を採用します。

### 採用決定: UnoCSS (オンデマンドCSSエンジン)
- **概要**: Tailwind CSSやWindi CSSの上位互換とも言える、超高速かつオンデマンドなCSSエンジン。
- **採用理由**:
  - **超高速なビルド**: 静的SPAビルド時のオーバーヘッドがほぼゼロで、Cloudflare Pagesでの配信サイズを極めて小さく抑えられます。
  - **Tailwind互換**: Tailwindのユーティリティクラス（`flex`, `bg-slate-900`など）がそのまま使用可能です。
  - **アトリビュートモード (Attributify)**: `border="~ red-500"` のようにHTML属性でスタイリングを記述でき、コードの可読性を大幅に向上させます。
  - **アイコン統合 (UnoCSS Icons)**: Pure CSSで動作する強力なアイコンエンジンを内蔵しており、追加の重いアイコンライブラリをインストールすることなく、何千ものアイコン（LucideやMaterial Design等）を高速・軽量に読み込めます。
  - **柔軟なカスタマイズ**: `uno.config.ts` で独自のカラーパレット（HSL）やガラスモフィズムのショートカットなどを容易に拡張できます。

---

## 5. OCR・推論エンジンの選定

ローカル環境（ブラウザ上）で高速かつ高精度に文字認識（OCR）を行うため、**ONNX Runtime Web (WASM バックエンド)** を採用します。

### 採用決定: ONNX Runtime Web (WASM) + Onnx OCR
- **概要**: 訓練済みのONNXモデル（例: PaddleOCRなど）をブラウザ上で実行するためのMicrosoft製推論エンジン。WASM/WebGL/WebGPUをバックエンドとして使用可能。
- **採用理由**:
  - **高精度なOCR**: 従来の文字パターンマッチングやTesseractに比べ、ゲーム画面のフォントや背景ノイズに極めて強いディープラーニングベースの文字認識（検出＋認識モデル）がローカルで動作。
  - **高速なローカル推論**: WebAssembly (WASM) バックエンドにより、CPUマルチスレッドを活かした高速推論が可能。
  - **軽量モデルの活用**: モバイル・ウェブ向けに最適化された軽量なONNX OCRモデルを採用することで、アセットサイズを最小限に抑え、Cloudflare Pagesの高速ロードを維持します。

---

## 6. テストフレームワークの選定 (TDD用)

エージェントガイドライン（`AGENTS.md`）で規定された **TDD (テスト駆動開発)** を実現するため、以下のテストフレームワークを採用します。

### 6.1 フロントエンド（TypeScript / React）: Vitest
- **概要**: Vite環境に特化した、超高速な単体・統合テストフレームワーク。
- **採用理由**:
  - Viteの設定（エイリアスやプラグイン）をそのまま共有できるため、設定が容易。
  - Jest互換のAPIを持ち、かつ実行速度が圧倒的に高速。
  - React Testing Library と組み合わせることで、コンポーネントのテスト（Red-Greenサイクル）をスムーズに回せる。

### 6.2 WebAssembly（Rust）: `cargo test` & `wasm-bindgen-test`
- **概要**: Rust標準のテストフレームワークおよびWASMブラウザ環境向けテストツール。
- **採用理由**:
  - ロジック部分（画像解析コア、計算コア）は、`cargo test` を用いてローカル環境で高速に単体テストを実行可能。
  - ブラウザ固有のAPI（Canvas等）に依存するWASMモジュールは、`wasm-bindgen-test` を使用してヘッドレスブラウザ上で挙動を検証。

---

## 7. 結論と決定事項

- **ホスティング**: **Cloudflare Pages**
- **フレームワーク**: **Vite + React (TypeScript)**
- **スタイリング / CSS**: **UnoCSS**
- **OCR・推論エンジン**: **ONNX Runtime Web (WASM)**
- **テストフレームワーク**: **Vitest** (フロントエンド) / **`cargo test` & `wasm-bindgen-test`** (Rust/WASM)
